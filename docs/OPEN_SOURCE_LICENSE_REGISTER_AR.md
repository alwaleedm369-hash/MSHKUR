## 1. قواعد القبول

نفصل دائماً بين:
- ترخيص كود التطبيق.
- ترخيص كل اعتماد مباشر وغير مباشر.
- ترخيص الأوزان والملفات المحولة ONNX/GGUF.
- ترخيص البيانات المستخدمة للتدريب/التقييم والعينات.
- حقوق الخطوط والأيقونات والصور والملفات الثنائية.
- شروط إعادة التوزيع والتعديل والاستخدام التجاري والإشعارات وبراءات الاختراع.

وجود LICENSE في المستودع لا يثبت ملكية أو ترخيص كل ملف بداخله. إذا كان الملف أو النموذج بلا دليل صريح: HOLD، لا توزيع.

## 4. بوابة اعتماد النموذج

لكل نموذج نضيف بطاقة مستقلة تشمل:
1. الاسم والمالك والمستودع/صفحة النموذج.
2. commit أو revision ثابت لا branch متحرك.
3. رابط LICENSE وModel Card وNOTICE.
4. ترخيص الوزن نفسه، وليس ترخيص أداة inference.
5. حق الاستخدام التجاري والتعديل وإعادة التوزيع الصريح.
6. مصدر بيانات التدريب وأي قيود معلنة.
7. checksum SHA-256 وحجم الملف وصيغته.
8. طريقة تنزيله وتخزينه وتحديثه.
9. إشعارات attribution المطلوبة.
10. قرار: APPROVED / HOLD / REJECT مع اسم المراجع وتاريخ القرار.

## 5. ما يلزم قبل إعلان الامتثال التجاري

- توليد lockfile من تثبيت نظيف وتثبيت الإصدارات.
- استخراج SBOM لجميع الإنتاج والاعتماديات العابرة.
- فحص تراخيص الحزم والملفات الثنائية والنماذج.
- حفظ LICENSE وNOTICE المطلوبة داخل التوزيعة.
- مراجعة تراخيص الصور التجريبية والخطوط والأيقونات.
- مراجعة أي patent clauses أو copyleft obligations.
- مراجعة قانونية للحالات غير الواضحة، ولا سيما MPL/LGPL/GPL/AGPL أو custom licenses.

## 6. سياسة القرار

- APPROVED: دليل كافٍ للاستخدام التجاري والتعديل والتوزيع مع استيفاء الإشعارات.
- HOLD: نقص دليل، نسخة غير مثبتة، ترخيص وزن غير واضح، أو lockfile مفقود.
- REJECT: non-commercial أو منع إعادة التوزيع أو تعارض مع نموذج المنتج.
