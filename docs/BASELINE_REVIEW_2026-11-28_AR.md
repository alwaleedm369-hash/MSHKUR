## 1. ملخص تنفيذي
المستودع الحالي ليس صفحة فارغة ولا يحتاج إلى إعادة بناء من الصفر. يحتوي بالفعل على React/Vite PWA، مسار Photo Studio محلي، معالجة دفعات، تخزين IndexedDB، اختبارات، خادم Express، مسارات API، سجل مهارات أولي، Smart Graph، MCP، ومجلدات تطبيقات منفصلة. يجب إعادة استخدام هذه الأجزاء والتحقق من ارتباطها الفعلي بالتطبيق المنشور قبل إضافة طبقات جديدة.

## 2. ما تم التحقق منه
- الفرع الافتراضي هو `main`، وهو غير محمي حالياً.
- نقطة الدخول الفعلية: `src/main.tsx` تستورد `src/App.tsx`.
- إعداد البناء: Vite + React + TypeScript؛ Node.js 22+.
- يوجد `package-lock.json` وتستخدم GitHub Actions أمر `npm ci`.
- `npm test` نجح في آخر تشغيل Pages رقم 41 بتاريخ 28 نوفمبر 2026.
- خطوة TypeScript/production build فشلت في التشغيل نفسه، ولذلك فشل نشر GitHub Pages لذلك الـcommit. لا نعتبر النسخة المنشورة محدثة بهذا الـcommit حتى ينجح نشر لاحق.
- مسار إزالة الخلفية الموجود في `src/App.tsx` يستخدم `@bg0/browser` داخل المتصفح، مع تطبيع الناتج ومراجعة أولية للقناع وحفظ محلي للأصل والنسخة المشتقة.
- `src/photoStorage.ts` يستخدم IndexedDB محلياً؛ هذا ليس تخزيناً سحابياً أو نسخاً احتياطياً لحساب.
- توجد بنية خادم في `server/` تشمل Express وAuth وDB وخدمات صور وGoogle/WhatsApp وMCP؛ وجود الملفات لا يثبت إعداد أسرار الإنتاج أو نجاح اتصال أي مزود.
- توجد سجلات مهارات في `skills/` و`src/shared/skills/`، وسير عمل في `workflows/`، وSmart Graph في `src/shared/graph/`.

## 3. تعارضات واجهة يجب معالجتها في Gate UX/UI
- التطبيق الذي يبدأ فعلياً من `src/main.tsx` هو `src/App.tsx`، وليس من الواضح أن صفحات `src/apps/home/HomeScreen.tsx` أو بقية micro-apps هي المسار الفعلي للمستخدم؛ يلزم توثيق routing/import graph قبل إعادة توصيلها.
- `App.tsx` يبدأ افتراضياً على شاشة المساعد، ويعرض ترويسة باسم/شعار، و`workspace-dock` سفلياً. هذه العناصر تتعارض مع قرار 28 نوفمبر: صفحة رئيسية عملية، لا شعار أو اسم ثابت في الواجهة، ولا Bottom Navigation.
- `GuestLanding.tsx` يعرض علامة في الترويسة وعينة قبل/بعد وروابط صور خارجية؛ يجب عدم اعتماده دون إصلاح الترويسة والتحقق من أن الأصلين يمثلان مقارنة معالجة صحيحة لنفس السيارة، وأن حقوق الصور مناسبة. المصغرات يجب أن تغيّر الصورة المعروضة فعلياً.
- توجد مكونات وواجهات متوازية؛ يجب تحديد المصدر الفعلي لكل شاشة قبل الدمج لتجنب تكرار تجربة المستخدم.

## 4. إصلاح بدأ على فرع منفصل
في `src/App.tsx` وُجد إغلاق/سطر dependencies زائد مباشرة بعد useEffect الخاص بحفظ اللغة والملف الشخصي والثيم. هذا تركيب غير صالح يفسر فشل خطوة TypeScript/Build. أزيل السطر الزائد فقط على فرع الإصلاح، مع الحفاظ على dependencies الصحيحة:
`[locale, isArabic, profileName, workspaceTheme]`.

**لم يتم بعد تأكيد نجاح الإصلاح بواسطة CI.** ينتظر الفرع تشغيل الاختبارات والبناء.
