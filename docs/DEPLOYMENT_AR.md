# تشغيل مشكور على استضافة Node.js

هذا دليل إعداد، وليس إعلاناً أن النشر الإنتاجي تم. لا تنقل المرور الحقيقي قبل نجاح الاختبارات ومراجعة الأمان.

## متطلبات الاستضافة

- استضافة تدعم Node.js 22 أو أحدث وتشغيل تطبيق Express طويل العمر.
- مجلد بيانات دائم قابل للكتابة خارج مجلد build المؤقت.
- HTTPS وشهادة TLS.
- مساحة كافية لقاعدة SQLite وملفات الصور؛ الحد الافتراضي 512 MB لكل معرض.
- نسخ احتياطي منفصل لقاعدة البيانات ومجلد الملفات.

إذا كانت خطة Hostinger لا تدعم Node.js process طويل العمر أو لا توفر تخزيناً دائماً، استضف API على خطة Node.js أو خادم منفصل، واجعل الواجهة static على أي CDN.

## خطوات النشر

1. فعّل GitHub Actions في المستودع حتى تعمل اختبارات CI.
2. راجع PR المرحلة الثانية وادمجه فقط بعد نجاح test/typecheck/build.
3. اربط المستودع أو ارفع المصدر إلى استضافة Node.js.
4. اختر Node.js 22.
5. نفّذ `npm install` (لا تستخدم `--ignore-scripts`؛ postinstall يطبق إصلاح BG0 وينسخ ملفات ONNX WASM إلى public/onnx).
6. نفّذ `npm run build`.
7. اضبط أمر التشغيل على `npm start`.
8. اربط النطاق وفعّل HTTPS.
9. نفّذ `npm run db:check` بعد أول تشغيل.
10. نفّذ `MSHKUR_BACKUP_DIR=/persistent/mshkur/backups npm run backup`؛ ينشئ نسخة SQLite متناسقة وملفات الصور مع فحص integrity وforeign keys وSHA-256.
11. انسخ مجلد النسخة كاملاً إلى تخزين خارجي، واختبر استعادته في بيئة منفصلة.
12. اختبر التسجيل، تسجيل الدخول، عزل معرضين، إضافة وتعديل سيارة، سير عمل الإعلان، معالجة الصور، تنزيل النتائج، وإعادة تشغيل الخادم.

## متغيرات البيئة

- `NODE_ENV=production`
- `APP_BASE_URL=https://your-domain.example` — النطاق الأساسي دون مسار.
- `PORT` — استخدم المنفذ الذي تحدده الاستضافة.
- `HOST=0.0.0.0`
- `TRUST_PROXY=1` فقط عند وجود reverse proxy واحد موثوق أمام Node.
- `MSHKUR_DB_PATH=/persistent/mshkur/data/mshkur.sqlite`
- `MSHKUR_STORAGE_DIR=/persistent/mshkur/storage`
- `MSHKUR_BACKUP_DIR=/persistent/mshkur/backups`
- `MSHKUR_TENANT_STORAGE_LIMIT_BYTES=536870912`

يجب أن تكون قاعدة البيانات ومجلد الملفات على قرص دائم، وليس داخل مجلد نشر يُستبدل عند كل release. إذا كان القرص غير دائم، لا تستخدم SQLite local في الإنتاج.

## النماذج والتكاملات

- لا تضع `LOCAL_LLM_BASE_URL` إلا إذا كان خادم llama.cpp محلياً أو على شبكة خاصة. العناوين العامة تُرفض.
- لا تحتاج روابط Google Maps الحالية إلى API key.
- Google OAuth غير مفعّل؛ الحساب المحلي يعمل دون Google Cloud.
- لا تضبط `MSHKUR_MCP_TENANT_ID` أو `MSHKUR_MCP_USER_ID` على خادم الويب العام. MCP المحلي يعمل بعملية stdio منفصلة.

## النسخ الاحتياطي والاستعادة

يجب أخذ نسخة متناسقة من SQLite وملفات التخزين معاً، والاحتفاظ بنسخ خارج الخادم واختبار الاستعادة دورياً. لا تنسخ ملف SQLite أثناء الكتابة باستخدام نسخ ملفات عادية؛ استخدم SQLite online backup API أو أوقف التطبيق مؤقتاً ثم انسخ قاعدة البيانات ومجلد storage معاً.

## حدود قبل الإطلاق

لا يزال يلزم إكمال اختبارات القبول، جدولة النسخ الاحتياطي خارج الخادم واختبار الاستعادة، استعادة الحساب، التحقق من البريد/استرجاع كلمة المرور، مراقبة الأخطاء، ومراجعة PDPL. هذه المرحلة لا تتضمن هذه الخدمات بعد.
