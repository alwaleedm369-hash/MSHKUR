# تصميم شاشات الجوال + واتساب بدون API — MSHKUR

تاريخ: 2026-11-18  
الحالة: مواصفات تصميم جاهزة للتنفيذ

## المبادئ غير القابلة للتفاوض

- Mobile-first وRTL عربي.
- لا API مدفوع في المسار الأساسي.
- واتساب = روابط `https://wa.me/` فقط (بدون مكتبات، بدون WhatsApp Business API، بدون unofficial clients).
- لا مكتبات مدفوعة أو ذات قيود استخدام تجارية مشكوك فيها.
- كل فعل خارجي (نشر، إرسال، حذف) يحتاج موافقة بشرية صريحة.
- REA أداة تطوير فقط، MCP محلي عبر stdio موجود بالفعل.
- الأصل محفوظ دائماً، النتائج مشتقة.

## 1. هيكل التنقل للجوال

### شريط سفلي ثابت (Bottom Navigation) — بعد تسجيل الدخول

| أيقونة | التسمية | الوجهة |
|--------|---------|--------|
| المنزل | مساحة العمل | DashboardHome / آخر مشروع سيارة |
| سيارات | سياراتي | قائمة السيارات + ألبوماتها |
| استوديو | التجهيز | استوديو الصور (أو مشروع السيارة النشط) |
| مهام | المهام | TasksPanel (Maestro) |
| المزيد | المزيد | مركز المالك + الإعدادات + المهارات |

الشريط يظهر فقط بعد تسجيل الدخول. للزائر: صفحة استقبال + أدوات سريعة بدون شريط سفلي.

### قواعد الجوال

- أهداف لمس ≥ 44px.
- مساحة آمنة للـ notch وشريط النظام.
- لا قوائم جانبية معقدة على الشاشات الصغيرة.
- كل شاشة مهمة لها زر رجوع واضح أو عنوان ثابت.
- الرسائل والأخطاء تظهر في أعلى الشاشة أو كـ toast خفيف.

## 2. الشاشات الرئيسية (تصميم جوال)

### أ. صفحة الاستقبال (Guest)

- بطاقة كبيرة في الأعلى: «ابدأ بتجهيز سيارة».
- شبكة أدوات سريعة (إزالة خلفية، طمس لوحة، تحسين، تجهيز إعلان).
- عند اختيار أداة: يطلب رفع صورة أو تسجيل الدخول لحفظ المشروع.
- لا إجبار على التسجيل قبل رؤية النتيجة الأولى.

### ب. مساحة العمل (DashboardHome) — بعد الدخول

- ترحيب مختصر + زر «سيارة جديدة».
- بطاقة «الاستوديو» الكبيرة.
- شبكة أدوات (4 بطاقات كبيرة).
- آخر سيارة أو قائمة قصيرة.
- حالة الاستخدام اليومية (حدود الصور/المسودات).

### ج. مشروع السيارة (الوحدة الأساسية الجديدة)

تبويبات أفقية قابلة للتمرير:

1. **الصور** — الألبوم + رفع + اختيار الغلاف.
2. **التجهيز** — أدوات التحرير على الصورة المختارة + اقتراحات الخطوة التالية.
3. **الإعلان** — مسودة من البيانات المؤكدة + تقرير النواقص.
4. **النشر** — صفحة عامة + رابط + QR + زر واتساب جاهز.
5. **النشاط** — سجل العمليات + الموافقات المتعلقة بهذه السيارة.

بعد كل نتيجة تحرير يظهر شريط اقتراحات:

- «طمس اللوحات في هذه الصور»
- «توحيد الخلفيات»
- «إنشاء مسودة إعلان»
- «تصدير الحزمة»

### د. استوديو التحرير (داخل مشروع السيارة)

- صورة كبيرة مع مقارنة قبل/بعد (مقبض سحب).
- شريط أدوات سفلي أو جانبي قابل للطي: إزالة خلفية | طمس | قص | استوديو مشاهد | تظليل زجاج.
- progress واضح + إمكانية إلغاء.
- حفظ كنسخة مشتقة تلقائياً عند النجاح.

### هـ. مركز المالك (Admin / Owner Center)

أقسام:

- ملخص سريع (سيارات، مهام جارية، موافقات معلقة، استخدام اليوم).
- **قائمة الموافقات** (الأهم): كل طلب نشر أو إرسال أو حذف يظهر هنا مع زر موافقة / رفض + سبب.
- سجل المهام (Maestro).
- مكتبة المهارات + حالة كل مهارة.
- إعدادات المعرض (اسم، slug، رقم واتساب للـ click-to-chat، رابط خرائط).
- حدود الاستخدام.

## 3. واتساب بدون API وبدون مكتبات

### الطريقة الوحيدة المسموحة حالياً

```text
https://wa.me/<رقم_دولي>?text=<نص_مجهز_مسبقاً>
```

- الرقم يُخزَّن في إعدادات المعرض (مركز المالك).
- النص يُولَّد محلياً من بيانات السيارة أو من قالب جاهز.
- الزر يفتح تطبيق واتساب على جهاز المستخدم.
- لا إرسال تلقائي، لا مكتبة، لا scraping، لا QR غير رسمي.

### أماكن الظهور

1. صفحة المعرض العامة (`PublicShowroom`): زر «تواصل عبر واتساب».
2. داخل مشروع السيارة → تبويب النشر: «أرسل تفاصيل هذه السيارة عبر واتساب».
3. بعد إنشاء مسودة إعلان: زر «نسخ النص + فتح واتساب».

### مثال نص جاهز

```
مرحباً، أستفسر عن السيارة:
[السنة] [الماركة] [الموديل]
السعر: [السعر] ر.س
المدينة: [المدينة]
رابط المعرض: [رابط الصفحة العامة]
```

يتم ترميز النص بـ `encodeURIComponent`.

## 4. الموافقات البشرية (إجبارية)

أي من التالي يمر عبر قائمة الموافقات في مركز المالك قبل التنفيذ:

- نشر سيارة في الصفحة العامة.
- إخفاء / حذف سيارة.
- أي اتصال بموصل خارجي مستقبلي.
- تفعيل مهارة مستوردة بعد المراجعة الفنية.

Maestro يقترح المهمة → يسجلها كـ «بانتظار موافقة» → المالك يوافق أو يرفض من الجوال → يُسجل القرار في سجل التدقيق.

## 5. ما لا نضيفه الآن

- WhatsApp Business API أو أي مزود مدفوع.
- مكتبات أتمتة واتساب غير رسمية.
- أي خدمة سحابية مدفوعة لإزالة الخلفية أو الكشف.
- Google AI Studio كجزء من التصميم أو التشغيل.
- لوحة إحصاءات معقدة كواجهة افتراضية.

---

## 6. الاعتماد على REA وMCP

- **REA**: يُستخدم فقط في مرحلة التطوير لتحليل سلوك أدوات مفتوحة المصدر مرخصة وإعادة تنفيذ الوظيفة بشكل مستقل داخل MSHKUR.
- **MCP**: الخادم المحلي عبر stdio موجود ويُبقى محدوداً بـ tenant واحد وصلاحيات owner/admin. لا يُفتح للعامة.

أي مهارة جديدة تمر بـ:
1. استيراد الوثيقة (SKILL.md) → مراجعة ترخيص.
2. كتابة handler آمن محلي.
3. اختبارات.
4. موافقة المالك قبل التفعيل.
