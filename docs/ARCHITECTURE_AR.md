# بنية مشكور — قرارات التأسيس

## المبدأ

MSHKUR نتيجة أولاً: المستخدم يختار مهمة واضحة، يضيف المدخلات، يرى المعاينة، ثم يعتمد الناتج. لا نبدأ بلوحة تحكم ضخمة ولا نكشف أسماء الوكلاء أو النماذج أو MCP للمستخدم العادي.

## الطبقات

1. **واجهة المنتج:** React + TypeScript + Vite + PWA، عربية RTL، mobile-first، light-first.
2. **API:** Node.js + Express، تحقق مدخلات، مصادقة، صلاحيات، سجل تدقيق، حدود طلبات.
3. **هوية المستخدم:** Firebase Authentication، Google Sign-In أولاً، ثم وسائل إضافية عند الحاجة.
4. **بيانات التشغيل:** Cloud Firestore مع قواعد وصول واختبارات emulator. كل مستند تابع لـ tenantId؛ لا ثقة في tenantId قادم من العميل دون تحقق.
5. **ملفات المستخدم:** Firebase Storage أو تخزين S3-compatible بعد مقارنة الكلفة والمنطقة والاحتفاظ. لا تحفظ الصور في JSON أو مجلد الخادم المؤقت كحل إنتاجي.
6. **المحرك:** سجل مهارات typed allowlist، مخطط مدخلات/مخرجات، سياسات تنفيذ، طابور مهام، retries محدودة، ومخرجات قابلة للتتبع.
7. **المعالجة المحلية:** أدوات المتصفح أولاً للعمليات الممكنة. العمليات الثقيلة تنتقل إلى Worker منفصل. لا API مدفوع في المسار الأساسي.
8. **التوصيلات:** Google APIs وWhatsApp وMCP adapters منفصلة، كل موصل له scopes وحالة اتصال واختبار handshake وسجل موافقات.
9. **الحوكمة:** سجل تدقيق، موافقة قبل الإرسال والنشر والحذف، حدود ملفات ومعدل، حماية أسرار، سياسات خصوصية واحتفاظ.

## مسار السيارات الأول

إضافة سيارة ببيانات موثقة ← رفع الصور الأصلية ← تجهيز الصورة مع حفظ الأصل ← معاينة ومقارنة ← مسودة إعلان من الحقول المدخلة فقط ← مراجعة المالك ← صفحة عامة/QR بعد الموافقة ← استقبال استفسار.

فحص السيارة وتشخيص الأضرار والتقييم الآلي خارج نطاق الإطلاق الأول.

## Firebase وGoogle AI Studio

- Google AI Studio Build يمكنه استيراد مستودع GitHub وربطه ثنائي الاتجاه.
- يمكنه إنشاء Firebase Authentication وCloud Firestore عند تفعيل Firebase integration.
- اختيار منطقة Firestore قرار بنيوي طويل الأمد؛ يجب اختياره بعد تقييم موقع المستخدمين والامتثال وارتباط خدمات Google الأخرى.
- Google Sign-In يحتاج إعداد مزود الدخول في Firebase Console وإعداد OAuth consent/authorized domains بحسب بيئة النشر.
- لا تضع مفاتيح Gemini أو service-account في الواجهة أو Git. إعداد Firebase web config ليس بديلاً عن Security Rules أو App Check.
- Firebase free tier ليس ضماناً أن كل خدمة مجانية بلا حدود؛ يجب ضبط quotas والتنبيهات والتحقق من الأسعار قبل التفعيل.

## قرارات مؤجلة حتى قياس الاستخدام

- Firestore مقابل PostgreSQL: نبدأ Firebase لتقليل تعقيد الهوية والتشغيل وربط AI Studio؛ نعيد التقييم إذا ظهرت احتياجات استعلامات/معاملات/تقارير لا تناسب Firestore.
- Trigger.dev مقابل BullMQ/Cloud Tasks: لا نضيف خدمة مهام قبل تحديد مكان الاستضافة واحتياجات الاستمرارية.
- MCP: لا نسمح بتسجيل خادم أو أداة من مخرجات نموذج. كل موصل يمر عبر allowlist وصلاحيات واختبارات.
- REA: أداة بحث/استكشاف تطويرية منفصلة، لا تُشحن كجزء من منتج مشكور.
