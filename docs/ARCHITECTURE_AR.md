# بنية مشكور — قرارات التنفيذ الحالية

## المبدأ

MSHKUR OS منصة تشغيل تبدأ من النتيجة، لا من لوحة تحكم تقنية. يختار المستخدم المهمة؛ يعمل Maestro والموظفون والمهارات في الخلفية. لا تظهر أسماء المكتبات والنماذج إلا في مساحة الإدارة.

## الطبقات

1. **الواجهة:** React + TypeScript + Vite + PWA، عربية RTL، mobile-first، واجهة فاتحة، وخط عربي محلي self-hosted.
2. **API:** Node.js + Express، مصادقة جلسات، حدود طلبات، تحقق مدخلات، صلاحيات وسجل تدقيق.
3. **الهوية:** حساب محلي بالبريد وكلمة مرور باستخدام scrypt وCookie HttpOnly. Google Sign-In موصل اختياري لاحقاً وليس شرط تشغيل.
4. **قاعدة البيانات:** SQLite مع WAL في النسخة الأولى، ومسارات tenant-aware. PostgreSQL عند الحاجة إلى عدة خوادم أو كثافة كتابة.
5. **الملفات:** مجلد تخزين دائم منفصل عن SQLite، مع file metadata وSHA-256 وعزل حسب tenant. يجب أن يكون القرص دائماً في الاستضافة.
6. **Maestro / REA:** Reasoning لتحديد المهارة، Extraction للتحقق من المدخلات، Automation لتشغيل handler مسموح. لا يسمح للنموذج بإنشاء كود وتشغيله تلقائياً.
7. **Skills Registry:** manifests مستقلة بصيغة Agent Skills، وhandlers في allowlist. المهارة التي لا تملك handler منفذاً تظهر غير متاحة.
8. **المساعدون:** أدوار متخصصة تُفعّل عند وصول المهمة؛ لا وكلاء دائمون يستهلكون الموارد بلا داعٍ.
9. **المعالجة:** sharp محلي للصور؛ أدوات ONNX/Transformers.js وllama.cpp اختيارية بعد اختبار النموذج والأوزان والأجهزة.
10. **الموافقات:** كل إرسال/نشر/شراء/حذف/مشاركة خارجية يتطلب موافقة مرتبطة ببصمة payload.
11. **الاتصالات:** Google OAuth وMaps وMCP وWhatsApp وBrowser automation موصلات منفصلة، ولا تُعرض كمتصلة قبل handshake واختبار فعلي.

## المسار الأول — MSHKUR Cars

إضافة سجل السيارة مرة واحدة ← رفع صور أصلية ← تحسين/تحويل الصورة مع حفظ الأصل ← معاينة قبل/بعد ← إنشاء مسودة إعلان من الحقول الموثقة ← مراجعة المالك ← تجهيز النشر ← موافقة قبل أي إجراء خارجي.

## قرارات تكلفة

- لا API مدفوع مطلوب للمسار الحالي.
- SQLite + التخزين المحلي يقللان تكاليف الخدمات في البداية، لكنهما يتطلبان قرصاً دائماً ونسخاً احتياطية.
- لا نضع نماذج كبيرة داخل Git أو ضمن تحميل الصفحة الأول.
- نموذج LLM المحلي اختياري عبر llama.cpp-compatible endpoint. لا يوجد fallback سحابي مدفوع.
- Google AI Studio ليس ضمن مسار التصميم أو التطوير أو التشغيل.

## حدود النسخة الحالية

التنفيذ الحالي أولي: خادم Node واحد، عامل مهام داخل العملية، أربع مهارات محلية، حساب مالك واحد لكل مساحة عند التسجيل. لم يكتمل بعد نظام دعوات الفريق، التخزين السحابي، تعدد العمال، OAuth، MCP، WhatsApp، أو النشر الخارجي.
