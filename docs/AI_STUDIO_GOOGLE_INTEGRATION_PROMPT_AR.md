# تعليمات استيراد MSHKUR وربط Google — دون إعادة تصميم

## ما الذي تستورده؟
استخدم أرشيف مصدر الفرع:
`build/phase-02-engine-core`

المشروع تطبيق React + TypeScript + Vite مع Express API وSQLite. ليس مشروعاً مولداً من Google AI Studio، ولا يُطلب من AI Studio إعادة إنشاء الواجهة.

## المطلوب من أداة التطوير بعد الاستيراد

1. افحص الملفات وقدم تقريراً قبل تعديل أي ملف.
2. حافظ على بنية React/TypeScript وExpress وSQLite وMaestro وSkills وMCP.
3. لا تحذف أو تستبدل واجهة MSHKUR أو سير العمل المحلي أو ملفات المعالجة.
4. لا تنقل مفاتيح OAuth أو أسرار Gemini إلى الواجهة أو Git.
5. أضف موصلات Google في مجلد مستقل، مع فصل كل خدمة وصلاحياتها.
6. استخدم OAuth Authorization Code مع PKCE حيث يناسب نوع التطبيق، وخزن refresh tokens مشفرة في الخادم.
7. اطلب أقل OAuth scopes ممكنة، ولا تطلب صلاحيات Gmail/Drive/Calendar إلا عند تفعيل ميزة تستخدمها.
8. ابدأ بتسجيل الدخول الاختياري، ثم Drive لحفظ ملفات المستخدم، ثم Sheets/Docs للتقارير، ثم Maps حسب احتياج المنتج.
9. Gemini موصل اختياري؛ لا تجعل الوظائف المحلية تعتمد عليه ولا تضف fallback مدفوعاً صامتاً.
10. WhatsApp: ابدأ بروابط wa.me ومشاركة المستخدم. لا تنفذ إرسالاً آلياً عبر WhatsApp Web أو مكتبات QR غير رسمية. لا تضف Business Platform إلا بعد مراجعة شروط Meta وتكلفتها وموافقة مالك المنتج.
11. أضف اختبارات لكل موصل، واختبر سحب الصلاحية وتجديد الرموز وفشل الشبكة وحدود الحصة.
12. لا تنشر أو تدمج إلى main تلقائياً.

## مخرجات مطلوبة قبل أي تعديل

- تقرير ما هو موجود فعلاً وما ينقص.
- مخطط تدفق OAuth لكل موصل.
- scopes المقترحة ومبرر كل scope.
- متغيرات البيئة المطلوبة دون قيم أسرار.
- التغييرات المقترحة على قاعدة البيانات.
- اختبارات وخطة rollback.

## تعريف الإنجاز

لا يُعد أي تكامل «مكتمل» لمجرد ظهور زر اتصال. يجب أن ينجح OAuth فعلياً، وتعمل القراءة/الكتابة المصرح بها، وتُسجل الموافقات والأخطاء، وتكون بيانات الاعتماد محمية، وتوجد اختبارات آلية.
