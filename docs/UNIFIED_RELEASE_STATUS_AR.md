# حالة تكامل MSHKUR — مرشح الإصدار الموحد

آخر تحديث: 2026-11-19

## مصدر النسخة

يعتمد خط التكامل على `feat/mshkur-engine-mobile-export` كأساس تجاري، وهو متقدم على `build/phase-16-persistent-paths`، والمرحلة 16 متقدمة على `build/phase-02-engine-core` بـ118 التزاماً. مرشح الإصدار الحالي `build/unified-release-candidate` يحافظ على هذا الأساس ويضيف تعديل نقطة الدخول.

## الوحدات الموجودة في خط التكامل

- واجهة زائر عربية RTL مع تجربة قبل/بعد وخيارات مشاهد والدخول المباشر إلى أداة تجهيز الصور.
- استوديو الصور وإزالة الخلفية محلياً وتحسين WebP والقص وطمس المنطقة يدوياً.
- استوديو المشاهد وتركيب خلفيات السيارات وأداة تضليل الزجاج اليدوي.
- ألبوم أصول السيارة وحفظ النتائج كنسخ مشتقة والمقارنة وسجل الإصدارات.
- سير عمل تجهيز إعلان السيارة وحزمة إعلان دون اتصال وطابور الموافقات وواجهة تحضير النشر إلى حراج.
- مساحة عمل المالك والمهارات والمهام والمحادثات والنمو والإدارة.
- Maestro والمهارات الخادمية وعزل بيانات المعارض وSQLite ومسارات التخزين الدائمة والنسخ الاحتياطي.
- واجهات الجوال والتحسينات البصرية وتصدير العلامة المائية القابل للضبط.

## تعديل نقطة الدخول

في `src/App.tsx` يبدأ المستخدم المسجل الآن من `studio` بدلاً من لوحة الرئيسية. تبقى شاشة الرئيسية متاحة من التنقل؛ لا تُحذف وظائف لوحة العمل. هذا يطابق مبدأ المنتج: افتح الأداة وابدأ بالمهمة، ثم انتقل إلى بقية المساحة عند الحاجة.

## ما لم نعتبره مكتملاً بعد

- لم يُثبت نجاح `npm test` و`npm run build` على runner نظيف لهذا المرشح؛ تشغيل GitHub Actions المتاح على رأس الفرع السابق انتهى بـ `startup_failure` قبل أن يقدم دليلاً على نجاح الاختبارات أو فشلها.
- بعض الموصلات خارجية اختيارية أو غير منفذة: Google OAuth/Drive/Gemini، خرائط مدمجة، WhatsApp Business API، كشف اللوحات والزجاج آلياً، وأتمتة المتصفح.
- يجب التحقق يدوياً من تنزيلات PNG/WebP والمقارنة وحفظ الأصول واستعادة النسخ الاحتياطية وتجربة الجوال قبل وصف النسخة بأنها جاهزة للإنتاج.
- لا تُرسل أو تنشر أو تنفذ إجراءً خارجياً دون موافقة صريحة، ولا يُعرض تكامل غير موجود على أنه متصل.

## بوابة الإصدار

1. تثبيت الاعتماديات على Node.js 22.
2. تشغيل `npm test` ثم `npm run typecheck` و`npm run build`.
3. تشغيل `npm run db:check` واختبار النسخ الاحتياطي والاستعادة على قاعدة اختبار.
4. اختبار المسارات الأساسية من الواجهة حتى API والتخزين، ثم اختبار الجوال.
5. مراجعة الأمان والخصوصية والتراخيص والأوزان قبل النشر.
6. بعد نجاح ما سبق فقط، تُنشأ حزمة ZIP نظيفة من نفس commit المعتمد.
