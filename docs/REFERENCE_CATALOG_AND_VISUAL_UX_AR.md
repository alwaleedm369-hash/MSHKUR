# مكتبة المشاريع والمراجع المرئية وواجهات MSHKUR

> وثيقة انتقاء هندسي ومرئي. وجود المشروع في هذه القائمة لا يعني اعتماده أو اختباره أو السماح بدمجه تجارياً. كل عنصر مرشح للمراجعة حتى فحص LICENSE والاعتماديات والأوزان والبيانات والأداء على بيئة MSHKUR.

## 1. قواعد الاختيار

1. الأولوية لمشاريع نشطة وموثقة ولها أمثلة تشغيلية واختبارات وإصدارات واضحة.
2. نفضل المكتبات الصغيرة القابلة لإعادة الاستخدام على استيراد تطبيق كامل.
3. نفصل ترخيص الكود عن ترخيص أوزان النماذج والبيانات والخطوط والأيقونات والصور.
4. لا نضيف اعتماداً لمجرد شهرته؛ يجب أن يحل حاجة أو يقلل مخاطرة/تكلفة.
5. لا نشغل كوداً مستورداً أو Skills غير موثوقة داخل خادم MSHKUR.
6. كل صورة مرجعية توصف: لقطة رسمية، Demo، مثال من المستودع، أو اختبار MSHKUR.
7. لا نستخدم صوراً محمية أو شعارات دون إذن؛ نحفظ النسبة والترخيص.
8. نسجل الإصدار وcommit SHA وتاريخ الفحص والثغرات ونتيجة تجربة صغيرة قبل الاعتماد.

## 4. شاشات MSHKUR المقترحة

المنتج يبدأ من الأداة والنتيجة، وليس من لوحة تحكم ضخمة. واجهات الإدارة تبقى خلفية وثانوية.

### التطبيق الأول: MSHKUR Cars

1. شاشة البداية/الاستوديو: صورة سيارة كبيرة في الوسط، اختيار مشهد الخلفية، دخول مباشر للأدوات، دون نصوص تسويقية طويلة.
2. ألبوم السيارة: شبكة صور أصلية، تحديد متعدد، ترتيب بالسحب، حالة كل صورة، وإظهار الأصل بوضوح.
3. محرر الصورة: مساحة عمل كبيرة، أدوات حول الصورة، شريط سفلي للجوال، تكبير/تصغير، تراجع/إعادة، وحفظ نسخة مشتقة.
4. إزالة الخلفية: مقارنة أصل/نتيجة، تحسين الحواف، خلفية شفافة، خيارات ظل، وتنزيل PNG.
5. طمس اللوحة: تحديد يدوي وتصحيح واضح؛ اقتراح آلي مستقبلي فقط حتى اختباره.
6. تضليل الزجاج: تحديد مناطق الزجاج يدوياً أولاً، معاينة درجة التظليل، وحفظ قناع قابل للتعديل.
7. استوديو الخلفيات: مشاهد ثابتة، ظلال/انعكاسات قابلة للضبط، ثم GIF/فيديو بعد بناء محرك فعلي.
8. تجهيز الإعلان: حقول السيارة المؤكدة، معرض الصور النهائي، معاينة الإعلان، وتنزيل المخرجات.
9. تفاصيل السيارة: البيانات، الصور الأصلية والمشتقة، سجل العمليات، الإعلان، وروابط المشاركة.
10. صفحة السيارة العامة: صور واضحة، مواصفات مؤكدة، وسيلة تواصل، وموقع المعرض.

### التطبيق الثاني: مساعد المعرض والعملاء

1. صندوق وارد لاستفسارات الموقع.
2. بطاقة عميل مرتبطة بسيارة ومصدر الاستفسار.
3. سجل تواصل وملاحظات ومهام متابعة.
4. مساعد صياغة ردود ومسودات لا ترسل دون موافقة.
5. تقويم مواعيد وتجارب قيادة عند تنفيذ الموصل.
6. سجل موافقات لأي إرسال أو نشر خارجي.

### التطبيق الثالث: المساعد الشخصي العام

1. شاشة محادثة ومهام.
2. اختيار المهارة أو الأداة عند الحاجة دون كشف تعقيد النظام.
3. قائمة المهام الجارية ونتائجها.
4. مساحة ملفات ومخرجات.
5. سجل مصادر وذاكرة بصلاحيات وشفافية.
6. تأكيد بشري قبل الأفعال الخارجية.

### التطبيق الرابع: طبقة الأدوات العامة

1. كتالوج الأدوات والمهارات.
2. صفحة تشغيل أداة مستقلة.
3. رفع المدخلات ومعاينة النتيجة.
4. سجل التنفيذ والأخطاء.
5. صلاحيات وموافقات.
6. واجهة تضمين تعمل داخل أي تطبيق من MSHKUR.

### التطبيق الخامس المحتمل: متصفح الإدارة المصغر

لا يعتمد كتطبيق مستقل قبل الحاجة. إن نُفذ، يبدأ بمتصفح محدود الصلاحيات، نطاقات مسموحة، حالة واضحة، موافقة قبل الإرسال/النشر/الحذف، وسجل نشاط.

## 5. مواصفات الصور والشاشات المطلوبة

لكل شاشة نسجل وننتج:
- صورة سطح مكتب 1440×900 أو نسبة مناسبة.
- صورة جوال 390×844 أو مقاس جهاز الاختبار.
- حالة فارغة.
- حالة تحميل.
- حالة نجاح.
- حالة خطأ قابلة للفهم والتعافي.
- فيديو قصير أو GIF للتفاعل المهم.
- ملف ملاحظات يشرح الهدف والتسلسل والعناصر والاستجابة ومصدر الإلهام.

لا نضع صوراً مولدة أو صور منتجات أخرى على أنها لقطات من MSHKUR. الصور المولدة تستخدم فقط كتصورات أولية وتوسم concept-generated. صور السيارات التجريبية يجب أن تكون مرخصة أو مصورة داخلياً وبموافقة أصحابها.

## 6. معايير التصميم الموحدة

- Arabic-first وRTL صحيح، مع دعم LTR للبيانات التقنية.
- Mobile-first؛ الجوال ليس تصغيراً لسطح المكتب.
- واجهة فاتحة ونظيفة، مساحة عمل واسعة، نص قليل وأيقونات مفهومة.
- المهمة والنتيجة في المقدمة؛ لوحة الإدارة لا تظهر للمستخدم العادي.
- لا نعرض أداة غير منفذة كأنها تعمل.
- لكل عملية أصل محفوظ ومعاينة وحالة وإلغاء آمن ونتيجة قابلة للتنزيل.
- دعم لوحة المفاتيح والتباين وأهداف اللمس وحالات التركيز.
- حالات تحميل وفراغ وخطأ ونجاح موحدة.
- لا حركة شكلية تؤخر معالجة الصور أو تستهلك البطارية.

## 10. الأولويات العملية

**P0 — الآن:** توثيق الأدوات الموجودة فعلياً، مكتبة المصادر، لقطات الواجهات الحالية، ومعايير التراخيص.

**P1 — تجربة:** مقارنة Konva مقابل Fabric.js لأدوات المناطق، وStorybook لتوثيق المكونات، وPlaywright لتدفقات القبول.

**P2 — لاحقاً:** كشف مناطق السيارة، ترتيب الصور، خرائط تفاعلية، inbox متعدد القنوات، ومراقبة الإنتاج.

**P3 — عند إثبات الحاجة:** PostgreSQL وRedis/BullMQ وQdrant وعمال منفصلون وbrowser automation.
