# تدقيق مشروع مشكور — الحالة الهندسية والتجارية

**تاريخ التدقيق:** 23 نوفمبر 2026  
**المستودع:** https://github.com/alwaleedm369-hash/MSHKUR  
**الفرع المرجعي:** `main`  
**حالة الإطلاق:** غير جاهز للإطلاق التجاري بعد

> هذا التقرير يميز بين الشيفرة الموجودة فعلاً، وما هو موصول في واجهة المستخدم، وما هو موثق فقط، وما لم يُختبر. وجود شاشة أو سجل مهارة لا يعني أن الوظيفة متصلة أو صالحة للإنتاج.

## 1. الحكم التنفيذي

MSHKUR ليس مجرد تصميم أولي؛ توجد نواة فعلية مبنية بـ React + TypeScript + Vite، وخادم Express، وقاعدة SQLite، ونظام مستخدمين/مساحات معارض، وملفات، ومهارات، ومهام، وموافقات، وصفحات معرض عامة. كما توجد إزالة خلفية داخل المتصفح باستخدام BG0/BiRefNet.

لكن النسخة الحالية **نواة منتج قابلة للتطوير وليست منصة متكاملة أو مجرّبة إنتاجياً**. أكبر فجوات الإطلاق هي:
1. النشر والتحقق: GitHub Actions لا يبدأ runner حتى الآن، لذلك لا توجد نتيجة build/test حديثة موثوقة.
2. تجربة الأداة: شاشة الزائر تبدأ بصفحة تسويقية طويلة، بينما المطلوب البدء مباشرة برفع صورة السيارة.
3. تشتت سير الصور: استوديو الدفعات وسير إنشاء الإعلان منفصلان؛ لا توجد مساحة سيارة واحدة تربط جميع النتائج بشكل مكتمل.
4. المساعد: محرك المهارات موجود، لكن الواجهة العائمة لا تستدعيه حالياً، والنموذج المحلي اختياري وغير معدّ افتراضياً.
5. التكاملات: الموجود روابط WhatsApp وخرائط Google، وليس WhatsApp bot أو Google OAuth/Drive/Maps API.
6. التخزين: المعالجة للزائر داخل المتصفح، لكنها لا تحفظ تلقائياً مشروعاً دائماً في حسابه أو ملف السيارة.

لا نعلن «جاهز» حتى ينجح بناء المشروع واختباراته، ويُختبر سير الصور على هواتف حقيقية، ويُثبت حفظ واستعادة البيانات.

## 2. معالجة الصفحة البيضاء — ما تم تغييره

### السبب

المشروع تطبيق Vite/React؛ ملف `index.html` يحمّل `/src/main.tsx` بوصفه مدخل التطوير. تشغيل GitHub Pages القديم كان يبني الملفات عبر Jekyll وينشر المصدر بدلاً من حزمة Vite المجمّعة. لا يستطيع المتصفح تشغيل JSX/TSX الخام كما لو كان ملف إنتاج.

### التغييرات التي رُفعت إلى `main`

- ضبط Vite لاستخدام `/MSHKUR/` عند البناء في GitHub Actions مع إبقاء `/` للتشغيل المحلي/الخادم.
- جعل مسار favicon تابعاً لـ `BASE_URL`.
- جعل مسارات ONNX WASM التابعة للمشروع تتبع مسار النشر، بدلاً من الاعتماد على الجذر المطلق.
- إضافة `.github/workflows/deploy-pages.yml` لبناء الواجهة، تشغيل الاختبارات، ثم نشر `dist`.
- إضافة `404.html` كمسار احتياطي لتطبيق React أحادي الصفحة، وإنشاء `.nojekyll`.
- إضافة `docs/GITHUB_PAGES_PREVIEW_AR.md` لشرح إعدادات Pages وحدودها.

### ما لم يثبت بعد

تشغيلات `verify` و`Deploy MSHKUR preview to GitHub Pages` الحديثة انتهت بـ `startup_failure` وقائمة Jobs فارغة. أي أن GitHub لم يبدأ بيئة التنفيذ ولم ينفذ `npm install` أو `npm test` أو `npm run build`.

يلزم من مالك المستودع:
- Settings → Pages → Build and deployment → Source = **GitHub Actions**.
- Settings → Actions → General: السماح بـ GitHub Actions وGitHub-hosted runners ومراجعة حدود الحساب/الفوترة إن استمر `startup_failure`.
- بعد تفعيل ذلك، يجب أن ينجح workflow كاملاً قبل اعتبار المعاينة مصلحة.

**GitHub Pages يعرض ملفات ثابتة فقط.** يمكنه معاينة React وبعض وظائف المتصفح، لكنه لا يشغّل Express أو SQLite أو ملفات المستخدمين. التشغيل الكامل يتطلب Node.js 22+ وقرصاً دائماً لـ `MSHKUR_DB_PATH` و`MSHKUR_STORAGE_DIR` وHTTPS ونسخاً احتياطياً.

|---|---|---|

| إزالة الخلفية | BG0/BiRefNet محلي داخل المتصفح مع مسار WebGPU/WASM | يعتمد على الجهاز وتنزيل النموذج أول مرة؛ لم تثبت الجودة على مجموعة سيارات وهواتف |
| تحسين الصور | تحسين/ضغط WebP عبر Sharp، وقيم إضاءة بسيطة داخل Canvas | ليس تحسيناً توليدياً أو ترميم تفاصيل نموذجياً |

| الخلفية/الظل | تركيب استوديو Canvas وظل/انعكاس تركيبي | ليست محاكاة فيزيائية أو توليد مشهد ذكاء اصطناعي |
| الإعلان | قالب نصي من بيانات المستخدم؛ مدقق حقول | إنشاء نص deterministic وليس LLM؛ لا يخترع مواصفات |
| سير المهام | Maestro يحفظ Jobs وحالاتها ويعالج المهارات المسموحة | ليس مخطط وكلاء مفتوحاً ولا صفوف عمل موزعة |
| سير الإعلان | فحص بيانات سيارة ثم صياغة مسودة من السجل | سير `car-studio-ad` معلن كـ hybrid لكن منفذ الخادم يرفض أي workflow ليس runtime=server |
| معرض عام | صفحة `/s/:slug` للسيارات التي يختار صاحب المعرض نشرها | نشر المنصات الخارجية غير متصل |

| مساعد التسويق | توليد بحث خرائط بحسب المدينة ونوع النشاط وفتح Google Maps | لا يجمع بيانات أشخاص ولا ينفذ حملات ولا يرسل رسائل |
| WhatsApp | روابط `wa.me` وفتح محادثة يدوياً | لا QR لربط جلسة شخصية، ولا مزامنة، ولا chatbot أو إرسال آلي |
| Google | deep links إلى خرائط Google | لا Google OAuth أو Drive أو Maps JavaScript API |
| المساعد | تصنيف محدود بالعبارات، وواجهة backend لنموذج محلي اختياري | النموذج غير مهيأ افتراضياً، وAIChatSheet غير موصول بـ onAssistantSend |
| PWA | إعداد VitePWA وmanifest | يحتاج اختبار build/install/update/offline على أجهزة فعلية |

### تفاصيل تؤثر في قرار الإطلاق

- `GuestStudio` يعالج حتى ثلاث صور في الدفعة ويعرض مقارنة وتنزيلاً ومشاركة WhatsApp. حد الزائر اليومي في هذه الشاشة يعتمد على `localStorage`، لذلك هو حد واجهة قابل للتجاوز بمسح بيانات المتصفح أو جهاز آخر، وليس حاجز إساءة استخدام موثوقاً.
- `GuestStudio` يضغط الصورة إلى حد أقصى 1600px قبل pipeline. يجب قياس ما إذا كان هذا يقلل تفاصيل الصور الكبيرة، وجعل الجودة/النسخة الكاملة خياراً عند ملاءمة الجهاز.
- `CarAdWorkflow` يتعامل حالياً مع صورة واحدة في الجولة؛ يعرض خطوات يدوية لطمس اللوحة، ثم بيانات الإعلان والمراجعة.
- ناتج الزائر يبقى في الذاكرة/روابط Blob ما لم ينزله؛ مسار الاستوديو ليس موصولاً بالكامل بحفظ أصل ومشتقات داخل سجل السيارة بعد تسجيل الدخول.
- شاشة الزائر `GuestLanding` فيها نصوص كثيرة وصورة «قبل/بعد» من صورتين تجريبيتين مختلفتين، وليست مقارنة للسيارة نفسها. هذا لا يطابق طلب الواجهة المباشرة، ويجب استبدالها بمساحة رفع/عمل فعلية.
- عند تسجيل الدخول يبدأ التطبيق من `DashboardHome`، بينما المطلوب أن تكون أداة الصور/مشروع السيارة هي نقطة الدخول الافتراضية، وتبقى الإدارة خلف تبويب ثانوي.
- `AIChatSheet` يعرض رسالة placeholder عند عدم تمرير callback. في `App.tsx` لا يمرر `onAssistantSend` إلى `CommercialShell`. توجد API لنموذج محلي، لكن لا يوجد provider مُعدّ تلقائياً.
- سجل الوكلاء يتضمن مراجع إلى `map-prospect-search` و`website-customer-chat`، وهذان المعرفان غير موجودين في `skills/registry.json` الحالي؛ يلزم توحيد سجل الوكلاء والمهارات قبل تقديمها للمستخدم كقدرات جاهزة.
- المستودع لا يحتوي حالياً على `package-lock.json` أو lockfile بديل. هذا يقلل قابلية إعادة البناء بنفس نسخ الاعتماديات ويجب إصلاحه قبل الإطلاق.

## 4. الفروع وطلبات الدمج

اعتمدنا `main` كمصدر الحقيقة، ولم ندمج الفروع التاريخية عشوائياً.

- #22: تحسينات جوال وعلامة مائية منفصلة؛ مفتوح/Draft وغير قابل للدمج المباشر.
- #23: تجميع mainline وتحسينات الجوال والعلامة المائية؛ مفتوح/Draft وغير قابل للدمج المباشر، ومتفرع من تاريخ متباعد عن main.
- #24: دمج إلى فرع `build/unified-release-mainline` وليس إلى main.
- #25: طلب عكسي مفتوح على ذلك الفرع.
- فروع المراحل القديمة وبعضها خلف main بعدد كبير من الالتزامات، وبعضها متباعد.

القرار: **لا نضغط Merge على هذه الفروع.** نأخذ التغييرات المفيدة بعد مقارنة دقيقة، ثم نعيد تطبيقها أو نعمل cherry-pick انتقائياً مع اختبارات. وجود ملف أو مكوّن في فرع لا يعني أنه صالح لنسخة main.

## 5. التصميم المعتمد لمشكور

التركيب الأنسب ليس لوحة تحكم كبيرة ولا مجموعة جزر منفصلة. هو ثلاث طبقات مترابطة:

### A. الأداة — نقطة الدخول

- فتح مباشر على رفع/تصوير صور السيارة.
- اختيار صورة واحدة أو دفعة، مع صور مصغرة أسفل مساحة العرض.
- النتيجة: مقارنة مرتبطة بالأصل نفسه، ونسخة شفافة أو خلفية استوديو بحسب اختيار المستخدم.
- أزرار إجراءات قصيرة: لوحة، زجاج، إضاءة، خلفية، قص، إعلان، تنزيل، مشاركة.
- لكل خطوة: تراجع/إعادة/إعادة معالجة، مع حفظ الأصل دائماً.

### B. مشروع السيارة — سياق العمل

كل سيارة لها مساحة موحدة تحوي:
- أصول الصور الأصلية ونسخاً مشتقة بإصدارات ووصفة تحرير.
- ترتيب صور السيارة واختيار الغلاف.
- نتائج الأدوات وبيانات السيارة المؤكدة.
- مسودة إعلان ونواقص البيانات ومراجعة واعتماد.
- حزمة إخراج (صور، نص، رابط صفحة، QR، مقاسات اجتماعية).
- سجل عمليات وملفات وتصدير ومشاركة.

بعد كل خطوة تظهر «الخطوة التالية» المناسبة من دون أن يضطر المستخدم إلى إعادة رفع الصورة أو البحث عن أداة منفصلة.

### C. المعرض والإدارة — خلف الكواليس

- مخزون سيارات وحالاته.
- صفحة معرض وصفحة مستقلة لكل سيارة.
- الوارد ومحادثات الموقع والمهام والمواعيد.
- صلاحيات مالك/مدير/موظف/مراجع وسجل تدقيق.
- موافقات صريحة قبل النشر أو مشاركة بيانات أو إرسال رسالة.
- إعداد هوية المعرض وQR وروابط الإحالة، ثم مؤشرات تشغيلية عند وجود بيانات فعلية.

## 7. البنية الداخلية المقترحة

نحتفظ بالنواة الحالية بدلاً من إدخال إطار عمل كبير قبل الحاجة:

1. **Skill manifest موحد:** id/version/description/input/output/runtime/dependencies/model/weights/license/permissions/cost/quality tests/error policy.
2. **Skill adapters:** محرك المتصفح للصور، handlers محلية لخدمات البيانات، وموصلات خادم اختيارية.
3. **Maestro:** queue وحالات persist/retry/cancel/approval وسجل أحداث. يُصلح workflow الهجين بدلاً من إخفائه.
4. **Project context:** معرف مشروع السيارة يربط الأصل والمشتقات والبيانات والمسودة والموافقات.
5. **Agent router:** تحويل الطلب إلى خطة معروفة ومحدودة، لا تنفيذ أوامر حرة. النموذج المحلي يساعد في الفهم والكتابة، بينما تنفيذ الأدوات يتم عبر allowlist.
6. **Human approval:** أي مشاركة/إرسال/نشر/حذف/تغيير خارجي يتطلب موافقة من صاحب الصلاحية.
7. **Provider interface:** نماذج محلية أو موصلات اختيارية لا تصبح شرطاً للمسار الأساسي ولا تنفّذ fallback مدفوعاً صامتاً.

## 8. تقنيات ومشاريع مرجعية — قرارات الاستفادة

### صور السيارات

- **BG0** موجود بالفعل في المشروع: مصدره Apache-2.0 ويستخدم WebGPU مع fallback إلى WASM، ويحمّل أوزان BiRefNet المثبتة ويخزنها محلياً. كود المكتبة وترخيص أوزان النموذج يجب أن يُراجعا كلٌ على حدة.
- **LumaCut** (MIT) مرجع معماري لتقسيم الإزالة إلى segmentation ثم ViTMatte/refinement ثم تنظيف لون الحواف. يدرس على عينات مرخصة قبل أي اعتماد.
- **Interactive Image Background Remover** مرجع وظيفي لتصحيح القناع بالفرشاة/النقاط/التكبير وUndo/Redo؛ لا ننسخ كوده ما لم يثبت ترخيص صالح.
- **CarFlow AI** مرجع لتسلسل رفع دفعة صور، إزالة الخلفية، تمويه اللوحات، توحيد المظهر، توليد وصف إعلان وتنزيل ZIP.
- **Spyne** مرجع لتجهيز صور المخزون، القوالب، الظلال/الإضاءة/الانعكاسات، والجولات المرئية. المراجع التجارية تؤخذ كتدفق وظائف لا كتصميم أو أصول محمية.

### المهارات والوكلاء

- **Agent Skills** صيغة مناسبة لتوحيد كل مهارة في مجلد يحوي `SKILL.md` وملفات `scripts/` و`references/` و`assets/` عند الحاجة. السجل الحالي JSON نقطة بداية لكنه يحتاج مواصفة/إصدارات واختبارات وترخيص.
- **OpenWorkflow** (Apache-2.0) مرجع لعمليات durable/resumable؛ لا حاجة لاستبدال Maestro الآن قبل قياس قصور محدد.
- **REA** أداة تطوير/MCP لفهم سلوك تطبيقات ومصادر مصرح بها. وثائق مشكور تسجلها كأداة تطوير فقط، وليس كمكون runtime. لم يتم تشغيل REA داخل هذه الجلسة.
- **Craft Anything** مشروع Rust مستقل في مرحلة alpha، له Desktop/CLI/MCP وسير Study → Build → Check → Refine يعتمد على coding agent. يصلح كأداة بحث/تحقق خارج مشروع مشكور بعد تثبيته محلياً ومراجعة حالته؛ ليس مكتبة React قابلة للنسخ أو بديل بناء مجاني بلا وكيل أو نموذج. لم يتم تشغيل Craft Anything داخل هذه الجلسة.
- **Carstio** (MIT) مرجع لإدارة ورش السيارات وأوامر العمل، لكنه موجّه للصيانة لا تسويق السيارات والمعارض.
- **ARK Core** (AGPL-3.0-only) ليس مرشحاً لنسخ كوده إلى منتج تجاري مغلق من دون تحليل التزامات AGPL؛ يمكن الاكتفاء بدراسة مفاهيم إدارة أوامر العمل.

## 9. WhatsApp وGoogle — الحدود الواقعية

- المسار المجاني الآمن في النسخة الأولى: رابط `wa.me`، نص جاهز، ومشاركة يدوية للصورة. ويمكن فتح قناة WhatsApp ليقوم المستخدم بالنشر بنفسه.
- هذا لا يساوي ربط جلسة WhatsApp Web أو استقبال الرسائل أو رد bot. لا نعتمد مكتبات غير رسمية لقراءة جلسات WhatsApp الشخصية أو أتمتة الإرسال؛ المسار الآلي الحقيقي يحتاج منصة Business رسمية وموافقات وسياسات وربما تكاليف.
- Google Sign-In وDrive وMaps Embedded كل موصل مستقل بموافقة وصلاحيات ضيقة؛ نبدأ بروابط الخرائط العميقة، ثم نضيف OAuth/Drive عند إعداد المالك. لا نضع أسراراً في الواجهة أو Git.
- Google AI Studio ليس نظام تشغيل أو قاعدة بيانات أو شرطاً لتطوير الواجهة. Gemini لا يدخل في المسار الأساسي المجاني؛ يمكن تجربته اختيارياً من دون fallback مدفوع صامت.

## 10. بوابات القبول قبل الإطلاق

### بوابة البناء

- تفعيل Actions runner.
- نجاح `npm test`.
- نجاح `npm run typecheck` و`npm run build`.
- إضافة lockfile واستخدام `npm ci` في CI.
- نجاح معاينة Pages للواجهة، ثم نشر خادم Node منفصل مع قاعدة وملفات دائمين.

### بوابة محرك الصور

- مجموعة صور سيارات مرخصة تشمل ألواناً وخلفيات وظروف إضاءة مختلفة.
- قياس جودة قناع العجلات/المرايا/الشبك والحواف والثقوب والهالات.
- قياس زمن التنفيذ والذاكرة على Android متوسط ومنخفض وiPhone.
- تصحيح قناع يدوي وإمكانية Reset/Undo/Redo.
- عدم ادعاء الكشف التلقائي للوحة أو الزجاج قبل detector واختبارات coverage.
- حفظ الأصل ومشتقات منفصلة وتصدير قابل لإعادة الإنتاج.

### بوابة المنتج والتاجر

- رفع دفعة ثم الانتقال من النتيجة إلى الإعلان من دون إعادة رفع.
- حفظ السيارة والملفات والمشتقات في مشروع واحد.
- مراجعة نص الإعلان من حقائق مؤكدة فقط.
- صفحة عامة لا تنشر إلا بعد تفعيل صاحب الحساب.
- QR ورابط ومشاركة وحزمة ملفات.
- اختبار صلاحيات tenant وعدم تسرب بيانات معرض إلى آخر.

### بوابة المساعد والتكامل

- إزالة رسالة placeholder من مساعد الواجهة، أو توضيح «غير مهيأ» إن لم يوجد نموذج.
- اختبار اختيار المهارة من الرسالة وتسجيل plan/job/result.
- نموذج محلي اختياري بلا مزود مدفوع تلقائي.
- اختبار قائمة الموافقات قبل أي فعل خارجي.
- اختبار WhatsApp links وفتح القناة والمشاركة اليدوية على أجهزة مدعومة.
- اختبارات OAuth وDrive/Maps لا تبدأ قبل تهيئة المالك للبيانات السرية والسياسات.

## 11. التغييرات المرفوعة إلى main في هذا التدقيق

- `vite.config.ts`: Vite base path لـ GitHub Pages/PWA.
