# REA وMCP في مشكور

## REA — Reverse Engineer Anything

REA ليس اختصاراً لـ Reasoning/Extraction/Automation. المقصود في مرفق المشروع هو مشروع **morluto/rea**: خادم MCP وأداة تحليل عكسي تساعد الوكيل على فهم التطبيقات والبرامج وسلوكها مع أدلة وحدود واضحة.

يستطيع REA تحليل تطبيقات JavaScript/Electron وملفات ثنائية و.NET ومواقع الويب، كما يتيح استخدام أدوات CLI. يعمل التحليل محلياً بحسب نوع الهدف والمحرك المتاح.

### كيف نستفيد منه في بناء مشكور

1. تحليل رحلات وتجارب أدوات مفتوحة المصدر نملك حق فحصها.
2. استخراج السلوك والمدخلات والمخرجات وحالات الخطأ، وليس نسخ الواجهة وحدها.
3. تدوين الأدلة والقيود والترخيص والاعتماديات.
4. إعادة تنفيذ الوظيفة في MSHKUR بصورة مستقلة.
5. كتابة اختبارات تقارن النتائج والسلوك المتوقع.

نستخدم REA كأداة تطوير/بحث، لا كخدمة runtime داخل خادم مشكور. لا نفك حماية تطبيقات، ولا نتجاوز تسجيل الدخول أو CAPTCHA، ولا ننسخ شيفرة أو أصولاً خاصة، ولا نتجاهل شروط الترخيص.

المصدر الرسمي: https://github.com/morluto/rea  
الحزمة الرسمية: https://www.npmjs.com/package/rea-agents

## MCP — Model Context Protocol

MCP هو البروتوكول الذي يربط الوكيل بأدوات وخوادم خارجية. REA نفسه يوفّر MCP server؛ لذلك العلاقة أن REA أداة تحليل، وMCP هو قناة الاتصال التي يعلن عبرها REA أدواته.

أضفنا خادم MCP محلياً عبر stdio فقط، مربوطاً بهوية owner/admin ومعرض واحد. لا نفتح MCP listener عاماً. سيأتي connector registry البعيد بعد تحديد المصادقة والصلاحيات ومصدر الخادم وحدود الأدوات. كل أداة مستوردة تمر بمراجعة ترخيص وأمن وتُسجل في allowlist. لا يسمح لأي خادم MCP بتنفيذ shell أو كتابة ملفات عامة أو الوصول إلى أسرار المعرض دون عزل وموافقة.

## حدود إعادة التنفيذ

ندرس السلوك العام والأدلة وننفذ وظيفة مستقلة. لا نستنسخ العلامة أو الشيفرة أو الأصول المحمية، ولا نزعم أن واجهة تشبه منتجاً ما تعني تطابقاً كاملاً معه.
