# MSHKUR — خطة التنفيذ الموحدة النهائية

**تاريخ الخطة:** 19 نوفمبر 2026  
**الفرع المستهدف:** `main`  
**المصدر المرجعي:** تقرير carAI، أرشيف Claude، تقارير وتوجيهات مشروع MSHKUR السابقة.

## القرار
تجميد توسع المهارات والتصاميم المتفرقة. يُعاد استخدام محتوى carAI كمرجع فقط، وتُنقل العناصر المرئية المفيدة إلى React داخل مشروع MSHKUR الرئيسي. يبدأ التنفيذ وفق P0، وتُقاس الإنجازات بالوظائف القابلة للاختبار لا بالوثائق أو mockups.

## المنتج
Tool-first: المستخدم يدخل مباشرة إلى المهمة، يرفع صور السيارة، يختار الأداة، يرى حالة معالجة حقيقية، يقارن الأصل والناتج، ثم ينزّل النتيجة. لا لوحة تحكم كبيرة كواجهة البداية ولا عبارات ترحيبية طويلة.

## Milestone 1 — الرحلة الأساسية
- [ ] Tool-first UI عربية RTL متجاوبة.
- [ ] Upload Session: اختيار/سحب الصور، معاينة، validation، إزالة، إدارة حالة.
- [ ] Processing API أو adapter فعلي لأداة واحدة، موثق حدود التنفيذ ومصدر المحرك.
- [ ] حالات queued/processing/succeeded/failed وretry.
- [ ] Before/After على ملف أصل ونتيجة حقيقية.
- [ ] Download للنتيجة، دون نتائج ثابتة أو placeholders.
- [ ] smoke/build واختبارات ومسار mobile.

## P0 — backlog
1. تدقيق main وتشغيل build وتثبيت baseline.
2. مراجعة mismatch بين props/مكونات الشاشة الحالية وإصلاحه.
3. استخراج عناصر HTML المفيدة من carAI وتحويلها إلى مكونات React، وعدم إبقاء صفحات HTML منفصلة كمنتج.
4. توحيد تصميم RTL ومكونات حالات التحميل/الخطأ/empty.
5. Upload Session.
6. تشغيل محرك حقيقي لإزالة الخلفية (أو أول tool أخرى) مع إظهار صريح أن إزالة الخلفية المحلية بالمتصفح هي محرك محلي وليس Processing API خادمي.
7. Before/After وdownload.
8. اختبار بناء وsmoke على الأجهزة الصغيرة.

## P1 — بعد ثبوت milestone
- Workflow الإعلان: بيانات السيارة، ترتيب الصور، وصف قابل للتعديل، مراجعة واعتماد، تصدير.
- إضافة أدوات طمس اللوحة وتحسين الصورة بحسب جودة المحرك واختبارات الجودة.
- دمج شاشة مراجعة/اعتماد من carAI مع المكون الموجود في main؛ لا إنشاء شاشة ثانية متفرقة.

## P2
Backend/DB/storage/auth حسب احتياجات إطلاق عام، اشتراكات، فرق/معارض، تكاملات DMS/قنوات نشر. لا يُدّعى اتصال خارجي دون API وصلاحيات واختبار.

## سياسة تجميد
- لا مهارات جديدة ولا HTML prototypes إضافية في هذه المرحلة.
- لا يضاف Skill إلا إذا كان له handler فعلي واختبار وحاجة ضمن backlog.
- لا تكرار لتصميم شاشة منفصلة؛ كل التصميمات المرجعية تتحول إلى components ضمن مسار المستخدم.
- لا نشر أو إرسال خارجي بدون موافقة صريحة.
- لا نعلن اكتمال أي مهمة دون اختبار أو دليل.

## Definition of Done
- الوظيفة تعمل على صور المستخدم فعلياً.
- حالات failure/retry واضحة.
- before/after يعرض أصل وناتج حقيقيين.
- download صالح.
- RTL/mobile/empty/error states.
- build واختبار smoke ناجحان.
- حفظ/حذف الصور وسياسة الخصوصية واضحة.
