# مختبر النماذج المحلي — سياسة التكلفة والترخيص

## الهدف

إتاحة نماذج مفتوحة المصدر للمساعدة في التصنيف واستخراج الحقول وصياغة المسودات، دون جعل خدمات LLM مدفوعة شرطاً لتشغيل الوظائف الأساسية.

## مساران للتشغيل

1. **المتصفح:** Transformers.js + ONNX Runtime Web لنماذج صغيرة ومهام محددة. يمكن استخدام q4/q8/fp16 حسب دعم النموذج والجهاز. تحميل النموذج يكون اختيارياً وبحجم معلن، لا ضمن أول فتح للتطبيق.
2. **خادم خاص:** llama.cpp لتشغيل نماذج GGUF، مع quantization مسبق على جهاز بناء/خادم مناسب. يربط عبر LocalModelProvider ولا يتصل بالإنترنت أثناء inference إذا تم تنزيل الأوزان مسبقاً.

## أدوات الضغط المقترحة

- llama.cpp / llama-quantize: تشغيل GGUF وتحويل/ضغط نماذج LLM المدعومة.
- ONNX Runtime + onnx-neural-compressor: quantization وweight-only quantization لنماذج ONNX.
- Unsloth: fine-tuning/QLoRA عند الحاجة، وليس جزءاً من مسار تشغيل كل طلب.
- Transformers.js: تشغيل نماذج ONNX داخل المتصفح؛ يدعم quantized dtypes مثل q4/q8 حيث يتوفر دعم النموذج.

## قواعد التنفيذ

- لا نحمّل أوزاناً ضخمة داخل Git أو حزمة النشر.
- تنزيل النموذج منفصل، بإظهار الاسم والحجم والترخيص وبصمة SHA-256 قبل التثبيت.
- الترخيص البرمجي لا يعني أن ترخيص الأوزان أو بيانات التدريب مطابق له.
- لا نعتمد أرقاماً تسويقية عن نسبة ضغط أو دقة دون benchmark على عينة MSHKUR عربية.
- لا نستخدم نموذجاً محلياً في حقائق السيارة أو السعر أو الحالة؛ هذه حقول موثقة من المستخدم.
- لا نستدعي خدمة سحابية مدفوعة كـ fallback تلقائي.

## الوضع الحالي

لم تُنزّل أوزان نموذج ولم يُشغّل LLM في هذه المرحلة. نضيف مزود النموذج بعد اختيار جهاز الاستضافة وتحديد الذاكرة وقياس نموذج عربي مناسب. الوظائف الأربع الحالية تعمل بخوارزميات deterministic ومكتبات محلية ولا تحتاج API ذكاء اصطناعي.
